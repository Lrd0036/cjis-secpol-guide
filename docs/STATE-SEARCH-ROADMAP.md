# Searching CJIS requirements by state

A Texas agency evaluating a cloud service needs two answers. Which FBI edition will its auditor use, and what does Texas require of the proposed deployment? The guide should answer both on one page, with the issuing authority, applicable dates and source beside each answer. FBI CJIS Security Policy §1.3 establishes a common minimum and allows jurisdictions to add protections. That makes it practical to maintain each federal edition once and link state provisions to it. [FBI policy v6.1, §§1.2–1.3, p. 1](https://le.fbi.gov/file-repository/cjis_security_policy_v6-1_20260625-1.pdf#page=22)

## What varies in practice

These public sources were checked on November 19, 2026. The pilot covers five states and one federal control excerpt. The Alabama, Illinois and Texas profiles include statewide rules, program conditions, local examples and unresolved questions. The Texas profile tracks the October access-policy revision and Texas Cyber Command reporting. Illinois covers the LEADS access and audit rules, dissemination, cloud review and incident reporting. The watchlist tracks an Alabama proposed rule and four Illinois ALPR bills. Each record identifies the people, data or program covered by its source. ### How an incident search changes by state

For **incident reporting**, the v6.1 federal reference is IR-6. Clause (a) concerns personnel notifying their own incident response function immediately, within one hour of discovery. Clause (b) names additional recipients. The state result needs its own trigger, recipient and reporting route. [FBI policy v6.1, IR-6, p. 171](https://le.fbi.gov/file-repository/cjis_security_policy_v6-1_20260625-1.pdf#page=192)

| Selected state and scope | State result |
|---|---|
| California · CLETS subscriber · security incident or data breach | Call California DOJ Computer Operations immediately and email Exhibit L to the CLETS Administration Unit. [California DOJ, §1.9.1, p. 38](https://oag.ca.gov/system/files/media/clets-policies-practices-and-procedures.pdf#page=38) |
| Michigan · criminal justice agency · digital or physical incident that significantly threatens CJIS data security or integrity | Report immediately to the Michigan State Police information security officer using the incident form linked by MSP. [Michigan State Police, Reporting CJIS Violations](https://www.michigan.gov/msp/divisions/cjic/cjis-compliance-unit/criminal-justice-agencies) |
| Alabama · State information or system, including systems operated on the State's behalf | State OIT IR-6 directs immediate reporting to the OIT Service Desk and sets a 24-hour limit from confirmation for agencies and vendors of the State. A CJI-specific intake for every Alabama county and municipality remains unverified. [OIT policy, scope and IR-6](https://oit.alabama.gov/wp-content/uploads/2025/01/Incident-Response-Policy.pdf#page=5) · [Alabama guide](states/ALABAMA.md#vendors-hosting-and-incidents) |
| Illinois · LEADS system security incident | The local agency security officer reports to the state CSA information security officer using the ISP form. It gives no separate hour limit for that handoff. A covered DoIT environment, personal-information breach or signed contract can trigger additional notices. [ISP incident form](https://isp.illinois.gov/LawEnforcement/GetFile/63ee8d54-396f-4e59-a157-7ef1f6d1d44c) · [Illinois reporting table](states/ILLINOIS.md#incident-reporting-and-breach-notification) |
| Texas · confirmed incident involving a TLETS or CJIS system | Notify the local security lead immediately and the DPS 24/7 Enterprise Technology Operations Center. DPS specifies one hour from discovery. A covered public entity also has a separate 48-hour statutory report. [DPS incident instructions](https://www.dps.texas.gov/section/crime-records/welcome-tx-cjis-security-office) · [Gov’t Code §2063.302](https://tcss.legis.texas.gov/resources/GV/htm/GV.2063.htm#2063.302) |

The sample can already answer a state-and-topic lookup from the repository root.

```sh
jq -r '
  . as $guide | .records[]
  | select(.jurisdiction == "US-CA" and .topic == "incident-reporting")
  | .summary, .locator, $guide.sources[.source].url
' data/state-search-pilot.json
```

## How to build the search

Seed the federal records from the two Requirements Companion spreadsheets already in the repository. Key each entry by FBI edition and exact control, enhancement or clause so that wording, priority and dates survive a version change. The existing control index can link readers into those records. The pilot establishes a state audit edition for Texas. Audit views for Alabama, California, Illinois and Michigan still need their own authority citations. [v5.9.5 companion](../sources/fbi/v5.9.5/requirements-companion-v5.9.5.xlsx) · [v6.1 companion](../sources/fbi/v6.1/requirements-companion-v6.1.xlsx) · [Control Index](CONTROL-INDEX.md)

1. **Index provisions.** Give each provision a stable ID, jurisdiction, issuer, topic, kind, applicability conditions, short answer and exact source locator. Capture program, audience, data class and access type as facets where they affect the result. Separate statewide requirements, program eligibility, agreements, audit instructions and sample forms. A state-only rule can be searchable before anyone maps it to an FBI control. Store any mapping with its FBI edition and distinguish an issuer's explicit reference from an editor's topic match. The pilot's `related_controls` entries are topic matches.
2. **Resolve jurisdiction and time before ranking text.** Start with the agency or program granting access. A vendor working for agencies in two states gets two selectable profiles. Tribal, territorial, federal and agency-specific authorities can have their own profiles and agreement links. For the selected state, date and purpose (audit or readiness), load the supported federal edition and state provisions. Keep the publication or revision date, effective window, audit window and last verification distinct. For an undated web page, show the observation date and mark earlier applicability unverified. If the audit edition is unconfirmed, label it and offer the published federal reference. After March 31, 2027, the current Texas source alone yields “successor audit edition needs confirmation.” [Version and Authority](VERSION-AND-AUTHORITY.md)
3. **Generate static pages and a small keyword index.** Keep reviewed JSON in Git. A build script can emit a browsable state directory, HTML pages such as `/states/tx/`, and one search index per state and federal edition. The browser loads only the selected indexes. Rank exact citations and control IDs first, then topic names and aliases such as “fingerprints” and “background checks.” Preserve state, topic, purpose and date in the URL so a reader can share the result. As the collection grows, split the research data by state and keep the stable IDs.
4. **Show the conditions alongside the answer.** Each hit should display the applicable agency/program, triggering condition, action, edition or date, issuer, section or page, last check and link to the original. Keep conditional matches visible when the user hasn't specified their access path. A state comparison should align results by topic and display each state's conditions separately. Let readers carry the citation and selected edition into the guide's existing assessment process. [System Assessment](../templates/SYSTEM-ASSESSMENT.md)
5. **Make research gaps searchable.** Track coverage by state *and topic* with a review date and owner. Distinguish unresearched, reviewed public sources, restricted material and unresolved conflicts. An Alabama cloud query can show the OIT procurement policy for State systems, a single-project ALEA example and the open question for county or municipal CJI hosting. A separate entry directs authorized users to the operational manuals portal. When sources disagree, show both citations and the deciding office for that program. Keep private agreements and system-specific decisions in the agency's authorized records. [Alabama guide](states/ALABAMA.md#vendors-hosting-and-incidents) · [AlaCOP manuals portal](https://cjicmanuals.alacop.gov/index.pl?cmd=FA_LOGIN)

## Rollout and upkeep

| Stage | Work | Completion check |
|---|---|---|
| First two weeks · Texas and Alabama | Start with the state manifests and federal companions. The Alabama profile now reconciles the October law against the live Code, identifies the old language still displayed for §41-9-650, and distinguishes the Commission, ALEA, state IT and local authorities. Use the remaining audit-edition and agency agreement gaps to guide the next source requests. | Weeks three and four · California and Michigan | Build the static lookup and add the two states' agency, program and incident-reporting records. Exercise searches by state name, postal abbreviation, program name, topic and control ID. | The incident query returns the route applicable to each state and agency. A Texas cloud provision stays within Texas results. An expired audit window and a restricted manual each produce a visible, distinct status. |
| Following months · expand by demand | Publish a directory for all 50 states with topic coverage visible. Prioritize the states readers work in and find each issuing agency, state code, program manuals, audit notices and public forms. Start each profile with audit edition, vendor access, hosting, incident reporting and CHRI use. | With one editor and a part-time reviewer, budget provisionally for two new states per month across those topics. Measure the first four, then set the pace using review and maintenance time. |

Check official listing pages and linked files weekly for changes. Preserve dated public snapshots where available, hash the bytes, and compare the relevant sections. An indexed California manual showed revision 9/25 at the same DOJ URL that served revision 10/26 during this review. Have a reviewer decide which provisions changed and record the effective date and superseded revision. A failed fetch keeps the last evidence visible with a review flag. Revisit each published profile quarterly and before a known transition. A change to a referenced rule should flag the affected assessments for reassessment.
